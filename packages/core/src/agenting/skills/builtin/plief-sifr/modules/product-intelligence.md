# Product Intelligence — frame before pixels

Answer “what reality must this surface make easier?” before layout exists. Produce `product_frame`, `user_jobs`, `constraints` and `invariants` in ExperienceIR. For a new/full surface or material ambiguity, read `../references/experience-archetypes.md`; skip it for local repairs.

## Infer from evidence

Use the request, fresh repository map, real copy/data, neighboring surfaces, routes, tests, existing assets and brand/system definitions. Record:

```text
WHO                  operator and relevant expertise/context
JOB                  job-to-be-done; entry point; completion condition
CONSEQUENCE           what failure costs; trust/consequence level
PRIMARY ACTION        one dominant action per view-state
SECONDARY ACTIONS     necessary but non-competing actions
INFO PRIORITY         must-see-before-action vs background/on-demand
SURFACE TYPE          marketing | app-shell | dashboard | table-heavy | form-flow |
                      editor | media | editorial | commerce | print/email/slides
EXPERIENCE ARCHETYPE  CONVINCE | OPERATE | ANALYZE | CREATE | COMPLETE |
                      EXPLORE | LEARN | MONITOR | BELONG (+ at most one support)
FREQUENCY / DENSITY   one-time -> repetitive; realistic 3/30/300/3000 volume
DEVICE / INPUT        dominant viewport, pointer, touch, keyboard, assistive paths
CONTENT TRUTH         real nouns, evidence, assets, unknowns and expected lengths
SUCCESS STATE         observable completion and how settlement should feel
```

Surface type says what container is being built; archetype says which behavior must dominate. A marketing page for an expert operations tool can be CONVINCE with OPERATE evidence; it should not become a fake dashboard or a generic campaign template.

## Translate pressure into decisions

- high-frequency + expert + dense -> stable placement, compact rhythm, keyboard continuity, short pointer travel;
- trust-sensitive/destructive -> visible consequences, explicit state, reversible path, proportional confirmation;
- exploratory/brand-led -> composition/media/motion budget may rise, but orientation and content truth remain;
- creation tools -> artifact first, direct manipulation, command/history/recovery clarity;
- monitoring -> state salience, chronology, confidence and response path beat decorative calm;
- completion flows -> error recovery, progress truth and mobile input behavior beat spectacle.

Write only structural or experiential invariants whose violation would reject a design. Translate weak evidence into assumptions with `impact_if_false`; do not fill unknowns with SaaS conventions.

## Honest gate

Search the environment before asking. When multiple material unknowns survive, send one consolidated question through Galileu's question ladder (maximum three prompts), while completing everything that does not depend on the answer. Never turn the product frame into a long interview form.

Protect downstream engine properties: Clarity · Agency · Fluency · Immediacy · Character · Reward. For important controls reason `affordance -> acknowledgement -> settlement`; never fake completion.
